# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Back-office / admin web app for a multi-location retail POS business (products, stock transfers/opname/adjustments, customers & loyalty, promos, sales reports, dashboard). Built on the Laravel 12 + Inertia v2 + React 19 starter kit, with Fortify auth, Wayfinder route generation, Tailwind v4, shadcn-style UI components, and `maatwebsite/excel` for imports/exports. UI text and flash messages are in Indonesian.

`.github/copilot-instructions.md` contains the Laravel Boost guidelines (package versions, PHP conventions, Inertia/Wayfinder/Pest/Tailwind rules). Follow them; key points are summarized below.

## Commands

```bash
composer run dev          # artisan serve + queue:listen + vite, concurrently
composer run setup        # first-time install, key:generate, migrate, build
npm run build             # production assets (needed if UI changes don't show)

composer test             # config:clear + pint --test + php artisan test
php artisan test --filter=DashboardTest      # single test / class
./vendor/bin/pest tests/Feature/DashboardTest.php

vendor/bin/pint --dirty   # format changed PHP (composer lint = pint on everything)
npm run lint              # eslint --fix
npm run format            # prettier on resources/
npm run types             # tsc --noEmit
```

Queue uses the `database` driver; Excel product imports run as queued jobs (`app/Jobs`), so `queue:listen` must be running for imports to complete.

## Architecture

**Request flow (web):** `routes/web.php` (all behind `auth` + `verified`) → controller in `app/Http/Controllers` → service in `app/Services` → `Inertia::render('<page path>', props)` resolving to `resources/js/pages/<page path>.tsx`. Mutations return `to_route(...)->with('success', '...')` redirects. Newer controllers inject a service via constructor promotion and keep logic out of the controller; follow that pattern (see `ProductCategoryController` / `ProductCategoryService`). Some controllers (e.g. `TaxController`) are stubs that render `comingsoon/index` with the old JSON implementation commented out.

**Multi-tenancy by entity:** Almost every domain table has `entity_id`. The current tenant is `auth()->user()->entity`; services scope queries with `where('entity_id', auth()->user()?->entity?->id)` and set `entity_id`, `created_by`, `updated_by` on writes. `HandleInertiaRequests` shares `auth.user` with `entity` and `employee` loaded. `EntityCheckingMiddleware` is an older mechanism (resolves employee/entity from an `x-employee-code` header and merges them into the request) still used on a few product routes.

**Two generations of backend code coexist:**
- `app/Services/*Service.php` — newer, Inertia-oriented services used by current controllers.
- `app/Helpers/` — legacy domain logic carried over from the original POS API: `Helpers/Services/<Domain>/` (creators, updaters, calculators such as `TaxCalculator`, `ProductCogsCalculator`), `Helpers/Data/` (DTOs), `Helpers/Queries/Report*Query.php` (report query builders), plus `Helper.php`, `UniqueCodeGenerator`, `ProrateCalculation`, etc. Reuse these for business rules rather than reimplementing.
- `app/Http/Responses/BaseJsonResponse` and `app/Http/Requests/Base*Request` belong to the legacy JSON style.

**Legacy reference copies:** `app_2/` and `database_2/` are snapshots of the original API project (not autoloaded). `database_2/migrations` holds the full domain schema (~96 migrations); `database/migrations` only has the starter-kit tables, so the real schema lives in the existing MySQL database. `routes/api.php` references controllers (`Kasir\*`, `Dashboard\*`) that don't exist in `app/` and is **not registered** in `bootstrap/app.php`. Consult these folders for context; don't edit them or wire them back in.

**Models:** Observers in `app/Observers` maintain derived data (stock, locations, customer points) — check them before changing stock/point writes. Status-like fields use enums in `app/Enums` (e.g. `StatusEnum`). Soft deletes + `deleted`/`restore` routes are a common CRUD pattern.

**Frontend:**
- Pages in `resources/js/pages`, layouts in `resources/js/layouts` (`AppLayout` with breadcrumbs), shared UI primitives in `resources/js/components/ui`, feature components in `resources/js/components/<feature>/`.
- Sidebar navigation is defined in `resources/js/lib/nav-items.ts`; frontend model/pagination types in `resources/js/lib/model.ts`; `toRupiah` and other helpers in `resources/js/lib/utils.ts`.
- Tables use `@tanstack/react-table` with the shared `data-table.tsx` / `table-pagination.tsx`; query-string filters via `hooks/use-query.ts`.
- `resources/js/routes`, `resources/js/actions`, `resources/js/wayfinder` are **generated by Wayfinder** from Laravel routes (Vite plugin regenerates them). Import route helpers from `@/routes/...` / `@/actions/...` instead of hard-coding URLs; don't hand-edit generated files.

## Conventions

- PHP: curly braces always, explicit return types, constructor property promotion; run `vendor/bin/pint --dirty` before finishing.
- Tests are Pest 4 (`tests/Feature`, `tests/Unit`). CI (`.github/workflows/tests.yml`) runs `npm run build` then `./vendor/bin/pest`; `lint.yml` runs pint/eslint/prettier.
- Don't add dependencies or new top-level folders without approval.
